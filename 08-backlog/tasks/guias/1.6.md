# Guia da task 1.6

**1.6 Reject a query shorter than 3 characters with the Portuguese message** —
[#41](https://github.com/Concord-API/API-5/issues/41) · Backend · 2h ·
[Sprint 1](../sprint-1.md) · [todos os guias](README.md)

## O que entrega

`GET /api/themes?q=ab` responde `400`, `application/problem+json`, no formato do
contrato:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "Requisição inválida",
  "status": 400,
  "detail": "Digite ao menos 3 caracteres para buscar."
}
```

## O que precisa saber

**1. Depende da 1.5.**

**2. A mensagem é exatamente** `Digite ao menos 3 caracteres para buscar.` — é a mesma que
o frontend mostra; um caractere diferente e as duas pontas divergem.

**3. O título é `"Requisição inválida"`.** O `ProblemDetailsTitles` do `Ratio.Api` troca
o título padrão do `400` por esse texto; os testes de `ProblemDetailsTitlesTests.cs` e
`ValidationProblemTests.cs` mostram como. Afirme o título no teste, para não depender de
suposição sobre qual caminho o aplica.

**4. Onde está a fronteira:**

| `q` | Resposta |
|---|---|
| ausente ou vazio | `200` com os temas de maior volume (1.7) |
| 1 ou 2 caracteres | `400` (esta task) |
| 3 ou mais | busca normal |

Conte os caracteres **depois de tirar os espaços das pontas**: `"  a  "` é um caractere.
Espaços só (`"   "`) contam como vazio.

## Testes

Em `Ratio.Api.Tests`, com a porta da busca mockada: `"ab"` dá `400` com o `detail`
exato; `"abc"` chama a busca; a busca **não** é chamada no caso do `400`.
