# Guia da task 9.7

**9.7 Return 404 with a Portuguese message for an unknown theme key** —
[#61](https://github.com/Concord-API/API-5/issues/61) · Backend · 2h ·
[Sprint 1](../sprint-1.md) · [todos os guias](README.md)

## O que entrega

`GET /api/themes/{key}` com uma chave que não existe responde `404` em
`application/problem+json`, com a mensagem **"Tema não encontrado."**.

## O que precisa saber

**1. Depende da [9.6](9.6.md).**

**2. Use o `Problem()` do controller**, como a 1.6 fez para o `400`:

```csharp
return Problem(detail: "Tema não encontrado.", statusCode: StatusCodes.Status404NotFound);
```

O `title` sai traduzido sozinho: o `ProblemDetailsTitles.cs` já mapeia `404` para
"Recurso não encontrado". Não escreva o título na mão.

**3. Três casos, uma resposta:**

| Requisição | Resposta |
|---|---|
| `theme_key` que não existe (`/api/themes/999999`) | `404`, "Tema não encontrado." |
| chave negativa ou zero | `404`, "Tema não encontrado.": nenhum `theme_key` é menor que 1, e o leitor devolve `null` |
| chave que não é número (`/api/themes/abc`) | `404` sem `detail`: com `{key:long}` na rota, ela não casa com nenhuma ação, e o `UseStatusCodePages` do `Program.cs` responde `problem+json` só com o título |

Confira no teste os três casos. Se `/abc` responder `400` pelo model binding, a restrição
`{key:long}` ficou fora da rota. Para `/abc`, a tela trata qualquer `404` como tema não
encontrado, então o `detail` vazio não atrapalha.

**4. O leitor devolve `null`** quando o tema não existe, e o controller transforma em
`404`. Nada de exceção para controlar o fluxo.

## Testes

Em `Ratio.Api.Tests`, com a porta mockada devolvendo `null`: status `404`, `Content-Type`
`application/problem+json`, `detail` "Tema não encontrado." e `title` "Recurso não
encontrado".

## Quem depende dela

A tela do tema (9.8), que mostra a mensagem quando alguém abre um link antigo.
