**1.2 Add the generated search columns and their indexes to the theme dimension** —
[#37](https://github.com/Concord-API/API-5/issues/37) · Backend · 3h ·
[Sprint 1](../sprint-1.md) · [todos os guias](README.md)

## O que entrega

Duas colunas novas em `dw.dim_theme`, calculadas pelo banco:

- `search_vector` (`tsvector`)
- `theme_name_norm` (`text`, minúsculo e sem acento)

E dois índices GIN:

- `idx_dim_theme_fts` em `search_vector`
- `idx_dim_theme_name_trgm` em `theme_name_norm gin_trgm_ops`

A especificação está em [Modelagem dos três bancos](../../../03-dados/06-modelagem-dos-bancos.md),
seção `dim_theme`. A modelagem também traz essas colunas em `dim_subject`, mas **a task é
só da `dim_theme`**; não mexa em `dim_subject`.

## O que precisa saber

Cada ponto abaixo foi conferido num Postgres 16.

**1. Migration nova, a `V003`.** Crie
`Ratio.Infrastructure/Migrations/Scripts/V003__theme_search_columns.sql`. Nunca edite a
`V001` nem a `V002`.

**2. `unaccent()` direto na coluna gerada não funciona.** O Postgres recusa com
`generation expression is not immutable`, porque o `unaccent` é `STABLE`. A saída é uma
função `IMMUTABLE` que chama o dicionário com o schema escrito por extenso:

```sql
CREATE FUNCTION dw.norm_pt(txt text) RETURNS text
LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT AS
$$ SELECT lower(public.unaccent('public.unaccent'::regdictionary, txt)) $$;
```

Com ela, `'Inscrição INDEVIDA'` vira `inscricao indevida`.

**3. O vetor de busca usa a configuração da 1.1 direto:**
`to_tsvector('dw.pt_unaccent'::regconfig, theme_name)`. Essa forma é `IMMUTABLE` e é
aceita na coluna gerada.

**4. A migration não cria extensão.** `pg_trgm` e `unaccent` são instaladas no schema
`public` por quem provisiona o banco.

**5. Um teste existente vai quebrar.** `DatabaseMigratorTests.cs` tem a lista fixa de
scripts (`V001`, `V002`); acrescente o `V003` nela.

**6. Testes:** siga o padrão de `PortugueseTextSearchTests.cs` (sobe o banco pelo
`PostgresFixture` e roda o `DatabaseMigrator`). Cenários que provam a task:

- ao inserir um tema, `theme_name_norm` sai em minúsculas e sem acento;
- `search_vector` casa uma busca escrita sem acento;
- escrever direto nessas colunas falha
  (`cannot insert a non-DEFAULT value into column ...`);
- os dois índices existem em `pg_indexes`.

**7. O Pipeline não muda.** O `pg_dump` que gera o arquivo de carga deixa as colunas
geradas fora do `COPY`, e o banco as recalcula na carga.
